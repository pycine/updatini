Capabilities

Built for the way
firmware actually ships.

A release console,
not a file dump.

Chunked by default

Bundles stream in 10 MiB parts with up to three retries, live throughput and an ETA. Large firmware never blocks the tab.

10 MiB partsretry ×3multipart

Target with intent

Send a release to the whole fleet or to one board ID. The target travels with the release.

whole fleet board · zaater-07

Every release indexed

Version, compatible string, target, size and timestamp — searchable and one click from the key.

Private by default

Bundles land in a private R2 bucket. There is no public download URL, and the API wants a token.

Edge-native

Workers serve the console and API. R2 holds the bytes, D1 holds the index. No server to patch.

Workflow

From build artifact
to indexed release.

Three steps.
No upload rituals.

01

Build a signed bundle

Produce a .raucb in your Yocto / RAUC pipeline. Updatini stores the signed artifact; it never needs your signing keys.

RAUC
02

Drop, name, aim

Upload it from the console, set the version and compatible string, then choose the whole fleet or a single board.

console
03

Indexed for the fleet

The Worker seals the multipart object and writes the release to D1, ready for your device update endpoint to serve.

R2 → D1

Device-side update checks and bundle downloads are intentionally out of scope. Bring your own endpoint — the release index is already there.

Security

A small surface
area, on purpose.

Every /api route is guarded by a bearer token. Bundles stay in a private bucket, and the token can be rotated with one command.

Read the security policy
  • Bearer-token API

    One 256-bit admin secret, checked on every API call.

  • Private R2

    No public bundle URL; object keys stay server-side.

  • HTTPS by default

    Cloudflare's edge handles transport. No certificates to manage.

  • Rotate in one command

    npm run token overwrites the secret and revokes the old token.
